# clio-brownbook — สมุดที่จด

ตัวนี้คือ **ฝั่งเขียน** ของ clio อีกฝั่งคือ `clio-echo` ที่เลขา Hermes ใช้อ่านโน้ตมาตอบ
ฝั่งนั้นเขียนอะไรไม่ได้และไม่เห็นข้อมูลดิบ **สรุปเกิดขึ้นที่นี่ที่เดียว**

เก็บข้อมูลได้ครบก็เพราะรันอยู่บนเครื่องเจ้าของ — commit ที่ยังไม่ push กับข้อความ
ที่เจ้าของพิมพ์ใน Claude Code มีอยู่ที่นี่ที่เดียวจริง ๆ ไม่มีทางไปดึงจากที่อื่นได้

## เลือกโหมดจาก arguments ก่อน

| พิมพ์ | ทำอะไร | ไปที่ |
|---|---|---|
| (ว่าง) · `--last` · `--week ...` | เก็บข้อมูล เขียนบันทึก push ขึ้น clio (ศุกร์เย็น/จันทร์เช้า) | ขั้นที่ 1–5 |
| `--meeting` | สรุปสัปดาห์ที่แล้วแยกตามโปรเจกต์ ในแชต (จันทร์บ่ายก่อนประชุม) | "โหมดประชุม" |
| `--meeting-ui` | เหมือน `--meeting` แต่ส่งเป็นหน้า Artifact ลิงก์เดิมทุกสัปดาห์ | "โหมดประชุม" |
| `--ask <คำถาม>` | ค้นย้อนหลังว่างานไหนทำถึงไหน | "ถามย้อนหลัง" |

เจ้าของไม่ทำงานเสาร์อาทิตย์ — รันวันศุกร์เย็นแล้วได้แค่จันทร์–ศุกร์ก็ครบแล้ว

## ขั้นที่ 1 — ดึงข้อมูลจริงก่อน อย่าเดา

```bash
S=~/.claude/skills/clio-brownbook/scripts
W=$(date -v-7d +%G-W%V)                      # สัปดาห์ที่แล้ว เช่น 2026-W35
python3 $S/collect.py --last --out /tmp/clio-$W.json
```

ช่วงอื่น: ไม่ใส่อะไรเลย = สัปดาห์นี้ · `--week 2026-W35` · `--since ... --until ...`
รอบนึงกินเวลาราว 2–4 นาที เพราะยิง GitHub ทีละ PR **สั่งแล้วรอ อย่ายิงซ้ำ**

ถ้าวันนี้เป็นวันจันทร์หรืออังคารแล้วผู้ใช้ไม่ได้ระบุช่วง ให้ทักก่อนว่าน่าจะอยากได้ `--last`
เพราะไม่ใส่อะไรเลยจะได้ข้อมูลแค่วันสองวัน

## ขั้นที่ 2 — อ่านแบบย่อก่อน แล้วค่อยเจาะ

ไฟล์ JSON ใหญ่หลายแสนตัวอักษร **ห้าม cat ทั้งไฟล์**

```bash
python3 $S/outline.py /tmp/clio-$W.json                          # ภาพรวมทั้งสัปดาห์
python3 $S/outline.py /tmp/clio-$W.json --pr 506                 # เนื้อ PR + ไฟล์ที่แตะ
python3 $S/outline.py /tmp/clio-$W.json --prompts iac-gitops     # ที่พิมพ์เอง รายโปรเจกต์
python3 $S/outline.py /tmp/clio-$W.json --day 2026-08-26         # เจาะรายวัน
```

เจาะเฉพาะเรื่องที่จะเขียนถึงจริง อย่าไล่อ่านทุกอัน

สัญลักษณ์ในภาพรวม
- `🟢 prod` — PR ยิงเข้า main โดยตรง ของขึ้น production แล้ว
- `🟡 dev →prod` — เข้า dev แล้ว **และ** มี PR release ตามไปถึง main ด้วย
- `🟡 dev` เฉย ๆ — **ยังค้างที่ dev ยังไม่ถึงมือผู้ใช้จริง**
- `⚪ branch` — ยังไม่เข้า dev ด้วยซ้ำ
- `⚠️` — ต้องเช็คมือ เช่นขึ้น merged แต่หา sha ใน main ไม่เจอ อาจโดน squash กลืน

## ขั้นที่ 3 — เขียนโน้ต

**โครงของโน้ตไม่ได้อยู่ในไฟล์นี้ อยู่ที่ `NOTE-FORMAT.md` ใน repo clio** เพราะฝั่งอ่าน
ต้องใช้โครงเดียวกัน เก็บไว้ที่เดียวจะได้ไม่หลุดกัน อ่านก่อนเขียนทุกครั้ง

```bash
gh api repos/thannnp/clio/contents/NOTE-FORMAT.md -H "Accept: application/vnd.github.raw"
```

เขียนลง `~/Documents/Obsidian Vault/Dev/Recap of completed tasks/<ปี>-W<เลข>.md`

กติกาที่ย้ำอีกที (ตัวเต็มอยู่ใน `NOTE-FORMAT.md`)
- **จัดกลุ่มตามเรื่อง ไม่ใช่ตามลำดับ PR** — PR สิบใบเรื่อง health probe ยุบเป็นหัวข้อเดียว
- คู่ dev→prod ของงานเดียวกันนับเป็น **เรื่องเดียว** อย่าให้ตัวเลขดูฟูเกินจริง
- ตัวเลขต้องมาจากข้อมูลจริง **ห้ามเดา** ไม่แน่ใจให้เขียนว่าไม่แน่ใจ
- หัวข้อ "งานที่ไม่มีร่องรอยใน git" ดูจาก `--prompts` เป็นหลัก งานไล่ debug
  แก้สิทธิ์ DB ตามงานคนอื่น พวกนี้ไม่มี commit แต่กินเวลาทั้งวัน
- ถ้าดูแล้วไม่แน่ใจว่างานไหนสำคัญ **ถามเจ้าของก่อนเขียน** อย่าเดาความสำคัญเอง
- **ใส่ป้ายโปรเจกต์** (`#horo #tongru #tripncab #cgos #here #other`) ท้ายทุกหัวข้อ `###` และทุก bullet
  ใน "ยังทำไม่จบ"/"งานที่ไม่มีร่องรอยใน git" + บรรทัด `projects: [...]` ใน frontmatter — ไว้ให้ค้นย้อนหลังได้
  ดูจากเจ้าของ repo: quintaura = horo · newsweetnew/tongru* = tongru · TripNCap = tripncab · cgos-* = cgos

### ขั้นที่ 3.5 — สรุปสั้นลง Weekly/ ด้วย (เจ้าของขอไว้ 14 ก.ย. 69)

เขียนอีกไฟล์ที่ `~/Documents/Obsidian Vault/Weekly/<ปี>/<ปี>-W<เลข> (<วัน–วัน เดือน>).md`
โครงตาม `Weekly/_Template — สัปดาห์.md` — สามเรื่องใหญ่ · ที่ถึง prod ด้วย · ค้าง/ต้องทำต่อ · ตัวเลข
ยาวไม่เกินหนึ่งจอ ลิงก์กลับตัวเต็มด้วย `[[<ปี>-W<เลข>]]` แล้วเติมบรรทัดใหม่บนสุดของ `Weekly/Weekly Index.md`
**ชื่อไฟล์ต้องมีวงเล็บวันที่** ไม่งั้น basename ซ้ำกับตัวเต็มแล้ว wikilink ชี้ผิด

## ขั้นที่ 4 — กรองแล้วค่อย push

```bash
python3 $S/redact.py /tmp/clio-$W.json /tmp/raw-$W.json
$S/publish.sh "~/Documents/Obsidian Vault/Dev/Recap of completed tasks/$W.md" /tmp/raw-$W.json
```

`redact.py` ตัดเนื้อ PR กับข้อความที่เจ้าของพิมพ์ออก เหลือแต่ชื่อ PR สถานะ ชื่อไฟล์
จำนวนบรรทัด และปลายทาง dev/prod — ก้อนนี้คือของที่วางไว้ให้ Hermes หยิบไปเขียนเองได้
ในอนาคตโดยไม่ต้องออก token ใบใหม่

**ถามเจ้าของก่อน push ทุกครั้ง** เพราะเนื้อในเป็นรายละเอียดงานบริษัท
`publish.sh` จะปฏิเสธเองถ้า repo ไม่ใช่ private หรือถ้า json ยังไม่ผ่าน `redact.py`

## ขั้นที่ 5 — สรุปในแชต (ส่งเลย ไม่ต้องรอให้ขอ)

เจ้าของอ่านอังกฤษไม่ถนัด อยากเห็นทั้งสัปดาห์ในจอเดียว และเห็นงานตัวเองให้ครบ
- หัวเรื่อง "สัปดาห์ที่แล้ว ทำอะไรไปบ้าง (วันที่)" + บรรทัดตัวเลขรวม (PR · ถึง prod · ค้าง dev · ใบงานที่ปิด)
- บอกความหมายป้ายไว้ต้นข้อความ: ✅ ขึ้น prod แล้ว · 🟡 ยังอยู่ dev · 🔍 ศึกษา/คุยกัน ยังไม่ลงมือ · 🔴 เร่ง
- หัวข้อมีเลข `## 1. ชื่อเรื่อง ✅` จัดกลุ่มตามเรื่อง ใต้หัวข้อเป็น bullet ไทยง่าย ๆ ว่าผู้ใช้/แอดมินได้อะไร
  ไม่ใส่เลข PR ไม่ใช้ศัพท์เทคนิค
- **ใส่งานให้เยอะที่สุด** รวมงานที่ไม่มีใน git (ลดค่า AWS ศึกษาเรื่องต่าง ๆ ดูแลทีม ดูแลข้อมูลลูกค้า ตอบคำถาม)
  ก่อนส่งไล่ `--prompts` ทั้งสัปดาห์อีกรอบเผื่อมีงานตกไป
- ปิดท้าย "ต้องทำต่อ (เรียงตามความเร่ง)" เป็นข้อมีเลข แล้วบอกจุดที่ไม่แน่ใจให้เจ้าของช่วยเช็ค

## โหมดประชุม — `--meeting` / `--meeting-ui`

ไม่รัน collect อ่านบันทึกที่ push ไว้แล้วใน clio เท่านั้น

1. `git -C ~/.cache/clio-repo pull -q --rebase` แล้วเปิด `2026/<สัปดาห์ที่แล้ว>.md` (`date -v-7d +%G-W%V`)
   **ไม่มีไฟล์ = บอกให้รัน `/clio-brownbook --last` ก่อน อย่าเขียนจากความจำ**
2. เช็คหัวข้อที่ค้าง dev ด้วย `gh` ว่ามี release เข้า main ตามไปหรือยัง ขยับแล้วเปลี่ยนป้ายเป็นขึ้นจริง + บอกวันที่
3. จัดกลุ่มตามป้ายโปรเจกต์ (`#horo` → Horo · `#tongru` → Tongru Academy · `#tripncab` → TripNCab · `#cgos` → CGOS · `#here` → HERE · `#other` → อื่น ๆ)
   ภาษาไทยง่าย ๆ ว่าผู้ใช้/แอดมินได้อะไร ไม่ใช้ศัพท์เทคนิค ใช้แบบขั้นที่ 5 แต่แบ่งตามโปรเจกต์ก่อน
4. `--meeting` → ตอบในแชต: ตัวเลขรวม · ความหมายป้าย · `## <โปรเจกต์>` แล้วเรื่องเป็นข้อมีเลข · งานที่ไม่มีในโค้ด · สัปดาห์นี้จะทำต่อ · จุดที่ไม่แน่ใจ
5. `--meeting-ui` → เขียน `report.json` ตามโครงในก้อน `<script id="report">` ของ `meeting/page.html`
   (status: `prod` `dev` `study` `urgent` · `refs` เป็นเลข PR ไว้ในส่วนที่กางดู · ห้ามใส่ชื่อลูกค้าหรือยอดเงินรายคน) แล้ว
   ```bash
   python3 $S/fill_meeting.py <scratchpad>/report.json <scratchpad>/meeting.html
   ```
   publish ทับลิงก์เดิม `https://claude.ai/artifact/UWSeb4Qaof3aHxNxva9zWz` (Artifact `url` = ลิงก์นี้ ต้อง `read` ก่อนถ้าเป็นคนละ session)
   ห้ามแก้ดีไซน์ใน page.html ระหว่างทำรายงาน — อยากเปลี่ยนหน้าตาให้แก้ template แยกต่างหาก

## ถามย้อนหลัง — "บั๊ก X ของ horo เดือนก่อน แก้หรือยัง ถึงไหนแล้ว"

ไม่ต้องรัน collect ไม่อ่านประวัติแชตในเครื่อง อ่านจาก repo clio อย่างเดียว

```bash
C=~/.cache/clio-repo; git -C $C pull -q --rebase      # ยังไม่มีให้ git clone https://github.com/thannnp/clio.git $C
grep -l '^projects:.*horo' $C/2026/*.md               # สัปดาห์ที่แตะ horo
grep -n -i -E 'แต้ม|reward' $(grep -l '^projects:.*horo' $C/2026/*.md)   # ค้นคำ ทั้งไทยและอังกฤษ
```

1. ค้นคำทั้งไทยและอังกฤษเสมอ (แต้ม/reward · คืนเงิน/refund) แล้วเปิดอ่านเฉพาะหัวข้อ `###` ที่มีป้ายตรงโปรเจกต์
2. เก็บเลข PR จากบรรทัด `- PR:` ของหัวข้อนั้น แล้วเช็คสถานะ **ตอนนี้** ด้วย `gh pr view` — บันทึกเป็นภาพ ณ วันจบสัปดาห์
   "ค้าง dev" ในบันทึกอาจขึ้น prod ไปแล้ว ดูว่ามี PR release เข้า main ตามไปหรือยัง
3. ไล่สัปดาห์ถัด ๆ ไปด้วยคำเดียวกัน เผื่อเรื่องเดียวกันมีต่อ (เจอ → แก้ → ขึ้น prod)
4. ตอบ: เจอสัปดาห์ไหน · ทำอะไรไปแล้ว · ตอนนี้อยู่ dev/prod · ค้างอะไร — ไม่เจอก็บอกว่าไม่เจอ อย่าเดา

## ข้อควรระวัง

- ถ้าสัปดาห์นั้นไม่มี commit ไม่มี PR เลย **อย่าเขียนสรุปเปล่า ๆ** ให้ถามเจ้าของว่า
  ไปทำอะไรมา แล้วเขียนจากคำตอบ
- ตัวสคริปต์ไม่ hardcode ว่าเจ้าของเป็นใคร ถามจาก `gh` กับ `git config` ตอนรัน
  ทับได้ด้วย `WEEKLY_GH_LOGIN` และ `WEEKLY_AUTHOR_MATCH`
- **ห้ามเชื่อว่า default branch คือ prod** — minigame-service ตั้ง default เป็น dev
  ตัว `collect.py` จัดการให้แล้ว ถ้าจะแก้ตรงนั้นอย่าเผลอถอยกลับไปใช้ `default_branch`
