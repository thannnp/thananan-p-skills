# สรุปงานรายสัปดาห์

คนอ่าน = **เจ้าของเอง กับ Hermes** (เลขา AI ที่ `~/hermes-secretary`) เพราะฉะนั้น
เขียนละเอียดเชิงเทคนิคได้เต็มที่ ไม่ต้องกลัวศัพท์ช่าง แต่หัวข้อต้องคงที่ทุกสัปดาห์
เพราะ Hermes จะดึงไปใช้ต่อ — เปลี่ยนชื่อหัวข้อเมื่อไหร่ ฝั่งนั้นอ่านไม่เจอ

## ขั้นที่ 1 — ดึงข้อมูลจริงก่อน อย่าเดา

```bash
S=~/.claude/skills/weekly/scripts
OUT=/tmp/recap-$(date +%Y%m%d).json
python3 $S/collect.py --last --out $OUT     # --last = สัปดาห์ที่แล้ว จันทร์ถึงอาทิตย์
```

ช่วงอื่น: ไม่ใส่อะไรเลย = สัปดาห์นี้ · `--week 2026-W35` · `--since ... --until ...`
รอบนึงกินเวลาราว 1–3 นาที เพราะยิง GitHub ทีละ PR

## ขั้นที่ 2 — อ่านแบบย่อก่อน แล้วค่อยเจาะ

ไฟล์ JSON ใหญ่หลายแสนตัวอักษร **ห้าม cat ทั้งไฟล์**

```bash
python3 $S/outline.py $OUT                                  # ภาพรวมทั้งสัปดาห์
python3 $S/outline.py $OUT --pr 506                         # เนื้อ PR + ไฟล์ที่แตะ
python3 $S/outline.py $OUT --prompts horoacademy-backoffice # ที่พิมพ์เอง เจาะรายโปรเจกต์
python3 $S/outline.py $OUT --day 2026-08-26                 # เจาะรายวัน
```

เจาะเฉพาะเรื่องที่จะเขียนถึงจริง อย่าไล่อ่านทุกอัน

สัญลักษณ์ในภาพรวม
- `🟢 prod` — PR ยิงเข้า main โดยตรง = ของขึ้น production แล้ว
- `🟡 dev` — ยิงเข้า dev/development เท่านั้น
- `🟡 dev →prod` — เข้า dev แล้ว **และ**งานตามไปถึง main ด้วย (มี PR release ตามหลัง)
- `🟡 dev` เฉย ๆ ไม่มี `→prod` — **ยังค้างอยู่ที่ dev ยังไม่ถึงมือผู้ใช้จริง**
- `⚪ branch` — ยังไม่เข้า dev ด้วยซ้ำ
- `⚠️` — ต้องเช็คมือ เช่น PR ขึ้น merged แต่หา sha ใน main ไม่เจอ (โดน squash กลืน)

## ขั้นที่ 3 — เขียนสรุป

เขียนลง `~/Documents/Obsidian Vault/Dev/Recap of completed tasks/<ปี>-W<เลข>.md`
ตามโครงนี้ **เป๊ะ ๆ** (Hermes อ่านตามหัวข้อ)

```markdown
# สัปดาห์ 35 (24–30 ส.ค. 2569)

## ภาพรวม
สองสามบรรทัด ว่าสัปดาห์นี้ "เรื่องหลัก" คืออะไร

## ขึ้น prod แล้ว
### <ชื่อเรื่อง ไม่ใช่ชื่อ PR>
- **ปัญหา** อะไรพัง/ช้า/เสี่ยง วัดได้เท่าไหร่
- **ทำอะไร** แก้ตรงไหน วิธีไหน
- **ผลลัพธ์** ตัวเลขหลังแก้ ถ้ามี
- PR: repo#123, repo#124

## ค้างอยู่ที่ dev (ยังไม่ถึงผู้ใช้)
### <ชื่อเรื่อง>
- ทำอะไรไปแล้ว · เหลืออะไร · ติดอะไรถึงยังไม่ขึ้น
- PR: repo#123

## ยังทำไม่จบ
- <งาน> — ค้างตรงไหน ต้องทำอะไรต่อ

## งานที่ไม่มีร่องรอยใน git
- <เช่น ไล่หาสาเหตุ RDS ล่ม, แก้สิทธิ์ฐาน prod, ตามงานคนอื่น>

## ที่ได้เรียนรู้ / กับดักที่เจอ
- <สิ่งที่สัปดาห์หน้าไม่ควรพลาดซ้ำ>

## ตัวเลข
PR <n> ใบ (merged <n>) · ถึง prod <n> · ค้าง dev <n> · รีวิวให้คนอื่น <n> ·
commit <n> ใน <n> repo · issue ที่ยุ่งด้วย <n>
```

กติกาการเขียน
- **จัดกลุ่มตามเรื่อง ไม่ใช่ตามลำดับ PR** — PR 10 ใบที่เป็นเรื่อง health probe
  ยุบเป็นหัวข้อเดียว
- คู่ dev→prod ของงานเดียวกัน (`#506` แล้ว `#508` release) **นับเป็นเรื่องเดียว**
  ไม่ใช่สองงาน อย่าให้ตัวเลขดูฟูเกินจริง
- ตัวเลขที่อ้างต้องมาจากข้อมูลจริง (เนื้อ PR, จำนวนบรรทัด) **ห้ามเดาเอง**
- **อะไรไม่แน่ใจให้เขียนว่าไม่แน่ใจ** ห้ามแต่งให้ดูเรียบร้อย
- หัวข้อ "งานที่ไม่มีร่องรอยใน git" ให้ดูจาก `--prompts` เป็นหลัก
  งานพวกไล่ debug, kubectl, แก้สิทธิ์ DB ไม่มี commit แต่กินเวลาทั้งวัน
- ถ้าดูแล้วยังไม่แน่ใจว่างานไหนสำคัญ **ถามเจ้าของก่อนเขียน** อย่าเดาความสำคัญเอง

## ขั้นที่ 4 — เอาขึ้น repo worklog ให้ Hermes อ่าน

```bash
$S/publish.sh "~/Documents/Obsidian Vault/Dev/Recap of completed tasks/2026-W35.md"
```

commit + push ขึ้น `thannnp/worklog` ตรง ๆ (repo ส่วนตัว ไม่ต้องเปิด PR)
**ถามเจ้าของก่อน push ทุกครั้ง** เพราะเนื้อในมีรายละเอียดงานบริษัท

## ข้อควรระวัง

- โน้ตนี้มีรายละเอียดงานบริษัท repo ปลายทางต้องเป็น **private** เสมอ
- `--last` จะได้สัปดาห์ที่ปิดจบแล้ว ถ้าสั่งวันจันทร์แล้วไม่ใส่ `--last`
  จะได้ข้อมูลแค่วันเดียว ให้ทักเจ้าของว่าน่าจะอยากได้ `--last` มากกว่า
- ถ้าสัปดาห์นั้นไม่มี commit ไม่มี PR เลย **อย่าเขียนสรุปเปล่า ๆ**
  ให้ถามเจ้าของว่าไปทำอะไรมา แล้วเขียนจากคำตอบ
